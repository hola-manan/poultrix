The project's core process is to generate a comprehensive agricultural advisory report for a given Area of Interest (AOI), crop, and sowing date. The entrypoint orchestrates fetching data from multiple external and internal sources, performing agronomic calculations, and assembling a structured report.

A successful run should produce a dictionary containing detailed sections on soil management, irrigation scheduling, fertilizer recommendations, growth and yield projections, and pest/disease risk. 

Key correctness checks include:
1.  **Data Provenance and Fabrication Disclosure**: The system is designed for 'graceful degradation'. If a live data source (like Open-Meteo for weather or ISRIC for soil) is unavailable, the system must fall back to default, fabricated data provided by the `jeevn.infrastructure.pseudo_satellite` module. A critical correctness requirement is that any such fallback MUST be explicitly declared in the `data_quality.fabricated_fields` list within the final report. The test should verify that if a data source is mocked to fail, the corresponding field appears in this list.
2.  **Input Propagation**: The input `lat`, `lon`, `crop_name`, and `sowing_date` must be correctly used in downstream calculations. For example, `lat` and `lon` should be used for all geospatial queries (weather, soil, terrain). `crop_name` should determine the phenology and crop coefficients (Kc). `sowing_date` should be used to calculate the 'days since sowing' for growth stage determination.
3.  **Internal Consistency**: The report's sections should be logically consistent. The growth stage derived from the sowing date and weather data should influence the irrigation and fertilizer recommendations. The soil analysis (e.g., texture, pH) should inform the soil management advice.
4.  **NDVI Analysis**: The input `ndvi_timeseries` data should be directly used to generate the `growth_yield.monitoring` section, including trajectory analysis and anomaly detection.
